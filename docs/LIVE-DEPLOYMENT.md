## Deployment configuration

Use a Node.js Next.js host. Set existing Supabase URL/public key/service-role key and voucher encryption key as deployment environment variables. Preserve the encryption key; never expose service secrets with NEXT_PUBLIC_. Do not upload .env.local, test-results, certificates or local login files.

Set NEXT_PUBLIC_APP_URL to the final HTTPS origin before building. Configure EMAIL_PROVIDER=resend, RESEND_API_KEY and EMAIL_FROM using a verified sending domain. Configure Supabase staff-auth Site URL and redirect allowlist for the deployed /auth/callback route. Staff authentication remains separate from applicant sessions.

Initially deploy with PAYSTACK_MODE=test, the test PAYSTACK_SECRET_KEY, PAYSTACK_LIVE_ENABLED=false and the controlled applicant rollout setting. Complete the provider-origin test checkout/webhook and applicant journey on the deployed origin.

After release checks and owner approval, configure together:

```dotenv
PAYSTACK_MODE=live
PAYSTACK_LIVE_ENABLED=true
PAYSTACK_SECRET_KEY=<live secret, deployment secret only>
NEXT_PUBLIC_APP_URL=https://<final domain>
APPLICANT_AUTH_ENABLED=true
DEMO_MODE=false
```

Save https://<final domain>/api/payments/webhook in the Paystack LIVE dashboard. Callback URLs are generated by the server using the configured origin. Rebuild/redeploy after changing the public origin. A dashboard mode toggle alone does not activate the app.

Run one approved real purchase, confirming the displayed amount and GHS before paying. GHS 1 pricing is a separate reviewed configuration; verify that it was applied and create a fresh quote. Confirm provider verification, one voucher/notification, duplicate handling, claim, applicant access and receipt. Restore the approved regular price after the controlled purchase. Do not call a synthetic fixture a live payment.
